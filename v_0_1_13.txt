Changes in v_0_1_13 relative to 0.1.12
======================================

- `src/manuscript/models`: added a shared `registry.json` hosted on `main`, with
  GitHub/GitVerse fallback and prioritized custom sources. The cached registry
  refreshes when missing, when a model key is unknown, or when all mirrors fail;
- model resolution now checks the model class, file size and SHA-256, and warns
  when the installed library is outside the tested compatibility range. Each model's artifacts and shared license are stored together in
  `~/.manuscript/models/<model-key>/`, with verified reuse of the old cache;
- model presets and TRBA pretraining now use the registry; added public helpers
  for downloading, inspecting, verifying, and removing cached model bundles;
- `src/manuscript/recognizers/_trba/__init__.py`: fixed a CUDA/ONNX Runtime
  inference bug in `TRBA` where the final incomplete batch shape could trigger
  severe recognition slowdowns on page-scale runs; the last partial batch is
  now padded to the effective batch size before ONNX inference and decoded
  back only for the original number of regions;
- `tests/recognizers/test_trba_infer.py`: added regression coverage for the
  padded last-batch inference path to ensure partial tail batches are executed
  as full effective-size ONNX runs while preserving the original number of
  returned predictions;
- `src/manuscript/api/base.py`: fixed CUDA DLL preload for ONNX Runtime on
  Windows by loading NVIDIA runtime DLLs from `site-packages/nvidia` and keeping
  DLL handles alive; this prevents ONNX Runtime from falling back to PyTorch
  DLLs and fixes cuDNN frontend sublibrary loading during CUDA inference;
- `src/manuscript/detectors/_east/__init__.py` and
  `src/manuscript/detectors/_east/utils.py`: made EAST PyTorch/training imports
  lazy so ONNX inference and CUDA session initialization do not import `torch`;
- `src/manuscript/recognizers/_trba/__init__.py` and
  `src/manuscript/recognizers/_trba/data/charset.py`: moved charset loading to
  a lightweight module and made TRBA training imports lazy so recognizer
  inference does not import `torch`;
- `src/manuscript/__init__.py`, package `__init__.py` files, and
  `src/manuscript/utils/__init__.py`: made heavy public exports lazy to keep
  `import manuscript`, detector/recognizer/corrector package imports, and
  visualization utilities free of unnecessary PyTorch imports;
- `src/manuscript/recognizers/_trba/model`: added the PARSeq decoder
  (`decoder_type="parseq"`; `parseq_linear` is an experiment configuration),
  `SEResNet31LiteV2` backbone, and optional TPS input rectification while
  retaining the existing attention decoder as the default;
- TRBA training and ONNX export now preserve PARSeq/TPS settings, use the
  decoder-specific loss and decoding length, and include focused architecture,
  export, training, and launcher tests;
- artifact downloads now show progress; incompatible model versions produce a
  warning while still allowing execution;
- checkpoint loading reports filtered keys; checkpoint and weight writes are
  atomic, CPU Torch RNG state is saved/restored, and TRBA training seeds NumPy;
- Pipeline uses the recognizer configured `batch_size` instead of hardcoding 32.

- recognizers now share validated Page/raw prediction handling and ONNX session
  creation; TRBA requires its own config/charset and supports float16 inputs;
- PPOCRRec normalizes native Paddle configs into an explicit CTC schema and
  requires declared units for optional length inputs; TrOCR validates generation
  settings and supports batched full-prefix/KV-cache decoding;
- added recognizer regression coverage and local-weight inference checks.
- TrOCR export now creates a dynamic-batch encoder and initial/cached decoders;
  runtime reorders KV-cache for beam search and supports legacy bundles;
- TrOCR export imports torch/transformers only when called, preserves the image
  processor resize backend, and supports use_cache/fp16 export options.
- TrOCR FP16 bundles keep image/state/cache IO in FP16; native uint8 antialias
  resizing reproduces the source processor's coefficient quantization and
  per-axis clipping/rounding without importing torchvision during inference.
- detector return_raw now returns compact geometry/classes/metadata; optional
  return_masks and return_outputs expose heavy data independently; Pipeline
  forwards the compact result as detector_result to compatible stages without
  retaining detector arrays in last_* snapshots.
